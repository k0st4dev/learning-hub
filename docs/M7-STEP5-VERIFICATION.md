# M7 step 5 — local password recovery

Verified 2026-10-12. `npm run password:reset` implements the trusted device owner's interactive recovery procedure. This is an OS-level capability; it does not prove email ownership and has no browser endpoint. It preserves the complete local curriculum and student records. Full M7 integration/native-browser and final A01–A26 acceptance remain open.

## Procedure and behavior

Stop the application. From the source repository, with the same data-directory configuration and tested Node runtime, run `npm run password:reset` without arguments. Enter the account email, review the selected account and type `RESET`. Enter a new password at the hidden prompt and press Enter. Restart the application and sign in with that password. Account/email normalization matches registration; password spaces and Unicode remain exact. Only the new password is required; the existing Argon2id policy and compromised-password blocklist apply.

The console is required to have interactive TTY input/output. Piped input, redirected output and all command-line arguments are rejected before any credential write. Readline output is muted during password entry, including paste and redraw; history is disabled. Ctrl+C/input close cancels, restores terminal mode and releases operation locks. Cancellation while hashing is checked before committing. Passwords stay only in the interactive operation's process memory and are never printed, stored in environment/arguments, written as plaintext, or retained in reports. Unknown driver errors are sanitized rather than logged with SQL parameters/hashes.

Recovery verifies the current reviewed migration history and checks database integrity/foreign keys. It opens the existing database only; it does not create an account, database, migration or seed. A selected-account/hash change during asynchronous hashing causes a conflict. Hash replacement, all-owner session revocation and selected-account login/password-change failure cleanup are one immediate transaction. Existing revoked timestamps are preserved. Installation and other-account throttle limits remain; an existing installation-wide block must expire normally. Account metadata/settings values and revisions, notes, checkpoints, course releases and learning/Continue are preserved; the general account update timestamp changes.

## Exclusive local operation

Documented development and production startup wrappers now hold `.local-operation.lock` until their child server exits. Recovery holds the same lock for its whole procedure, so startup and recovery refuse one another. Build does not take this lease. Metadata records the operation, PID and owner nonce; release verifies ownership before unlinking and is idempotent. Data-path resolution rejects reserved/public paths, including symlinks resolving into them. Lock/private database filenames are excluded from Git even for a custom data path inside the repository.

Recovery also reserves the configured loopback port (catching an older/unmanaged server) and holds the existing `.setup.lock` against migrations. A preexisting/stale lock is never automatically deleted. Normal exit releases resources; hard process termination can leave a lock and fails closed. Follow the README's explicit stale-lock inspection procedure; removing locks never means removing the database. General backup/restore/content-upgrade orchestration remains M8 work.
