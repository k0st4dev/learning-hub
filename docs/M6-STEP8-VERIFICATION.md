# M6 step 8 — owned resource library filtering service

Date: 2026-10-08. Specification section 16. This increment supplies the validated filter/read model; visible library controls and final acceptance are not complete.

## Delivered contract

- `readResourceLibrary` derives ownership and the pinned release from the session, rejects absent enrollment and stale expected-account identity, and requires published full curriculum. It never chooses another user or a newer release from submitted parameters.
- Strict `resourceQuerySchema` accepts q/page and repeated source/type/module/week/day/requirement parameters. Query bounds and normalization reuse course search: 100 UTF-16 code units, eight whitespace words, literal AND tokens, escaped parameterized SQLite LIKE. Empty q lists the library. Unknown parameters/duplicate scalar values are invalid; unknown valid source/scope values produce zero results. Page range is 1–10,000. Sources allow sixteen values of at most 200 characters; existing scope limits are eight. These are documented minor input bounds.
- Type values retain database identifiers: documentation/article/video/course/tool/reference/practice/guide. Requirement values preserve required/optional/reference/conditional; conditional is never relabeled as required or optional. Filters combine with AND and multiple values within a dimension with OR.
- All contextual dimensions, including requirement, must match **the same resource use**. A required Day 1 use cannot combine with an optional Day 2 use to satisfy optional + Day 1. Module/week/day come from actual ancestors; a week/handbook use has no invented day. Text matching covers the shared resource title/provider/description/original URL/assignment index, independently of which contextual use matched.
- Twenty-five resources per page with deterministic original-title, then ID code-unit ordering, independent of relevance, locale or insertion order. Empty/out-of-range pages preserve the true count. No-context resources remain visible without contextual filters.
- Entries preserve all resource metadata, original/reviewed URLs, source/link status/check date, exact assignments/section locators, all contextual uses and breadcrumb reading links. `matchingUseIds` identifies matching contexts without hiding the other uses. Related days are deduplicated and numbered in source order. Unresolved/unavailable resources remain present; no link is invented or live-checked.
- Shared `catalogScopeOptions` preserves the existing search choices and supplies the same six phases/26 weeks/182 days to the following resource UI. No persistent schema/index, dependency, importer, published release, curriculum source or learner-record changes. The existing derived TEMP search index remains disposable.

## Metadata discrepancy and agreed follow-up

The existing M2 importer assigns **reference to all 69 resource types and all resource uses**, and uses canonical resource titles as source/provider values. This conservative metadata does not distinguish the original course/documentation/practice or mandatory/optional instructions. Thus the current pinned release truthfully has empty documentation/course/required/optional filter results. The new service exposes observed metadata coverage and does not silently rewrite published content to make those filters look populated.

The discrepancy was explicitly flagged before classification changes. The user chose: **finish filters, then review labels**. The next increment must review original source-backed classifications and propose a separate immutable-release-compatible interpretation mechanism. No proposed classification mechanism or content migration was implemented here. Full resource-filter UX/semantic acceptance remains open until that work and the UI are verified.
