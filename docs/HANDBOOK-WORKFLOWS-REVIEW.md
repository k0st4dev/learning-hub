# Remaining handbook workflows — proposed behavior

Date: 2026-10-09. **Review only; none of the proposed controls is active.** The original five guides remain available in full. The [machine-readable proposal](handbook-workflows-proposal.json) contains every exact original paragraph, Word style, text digest and CSV destination, separately from pending product interpretations.

## Recommended interpretation

Use **temporary, advisory tools** for the remaining handbook checks. Their marks describe the current review, concept or debugging attempt; they do not represent completed curriculum units. Display an added notice before the controls: “Temporary review. Marks reset when you leave or reload. This does not save course progress.” Keep original Serbian paragraphs expanded and distinguish the added interface from source content. Do not hide daily AI rules or completion criteria.

Use component memory only: no localStorage, sessionStorage, cookies, API or database writes. Reset on leaving/reloading the guide and when the rendered account/release/guide identity changes. Clear this review clears only temporary marks. A newly signed-in student must never inherit another account's marks. Native labeled checkboxes, visible focus and ordinary buttons support keyboard use. Announce optional review status politely without claiming Saved, Completed, Mastered or AI permission. Retain the existing Return to learning action through `/continue`; the tool must not change the active study cursor.

This is an explicit product interpretation requiring approval. The specification defines B/C/E as handbook tools and states that handbook has no completion requirement; it does **not** define saved sessions, per-concept histories, revision rules or persistence for their marks. The requirement that confirmed course progress survives restart continues to apply unchanged to the 364 required units, preparation, notes and scorecards. Calling temporary marks Saved would violate that distinction.

If durable handbook marks are wanted, agree a separate account/enrollment/release-owned SQLite contract, reviewed migration, explicit confirmed saves/revisions, conflict/retry and backup/update semantics before implementation. Do not store them as lesson/task/preparation progress, add units to the denominator, encode structured state in private-note text or silently use browser storage. That option expands the implementation beyond the proposed temporary tools and is not approved by this review.

## Reuse and actual gaps

- Existing preparation and exercise components save owned progress and enforce task requirements, evidence, revisions and reopening. Their persistence hooks and progress records must not be reused for these advisory marks. Reuse visual styles and ordinary checkbox/button patterns only; centralize the new small temporary checklist component across B/C/E.
- Existing `CopyableText`, source rendering, handbook fragment navigation and `/continue` are reusable. The original blocks stay accessible even if an added tool cannot initialize. The account/release/guide key comes from the authenticated page, rather than client-entered identity. A server response cannot be inferred from a purely local check action.
- Private notes already persist in SQLite. The notes service validates ownership and release membership for content items; the actual note editor is currently rendered only on day/study/exercise pages. Extending guide notes is possible but is not required or proposed here. Students can keep durable reflections in their existing study notes after Return to learning; the tools must not write into those notes automatically.
- Appendix A copy, D's saved scorecard and all eight prompt templates are implemented. All eleven guides have source-heading navigation/return, and handbook text is searchable. The original full B/C/E/F/G content is readable; their added workflow presentations remain open. Completed-course Progress already links to the final retrospective and G.
- Daily day/study/exercise views do not yet expose the specification's collapsed supporting handbook shortcuts. Propose one shared, optional help panel linking to How to study (daily operating system/ritual), AI protocol, B/C/E and relevant C-to-F help. Keep daily AI policy and completion instructions expanded. These are added navigation aids, not assertions that each original daily assignment explicitly names every guide.
