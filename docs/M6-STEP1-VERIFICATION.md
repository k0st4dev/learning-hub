# M6 step 1 — private note persistence and owned API

Verified 2026-10-06. This is the approved backend/API increment, not the complete M6 milestone or final MVP acceptance. Notes UI is the next separately approved step.

## Delivered contract

- Direct server services `readNote` / `saveNote` and `GET` / `PUT /api/notes/:itemId`, using the existing reviewed `note` table. No migration, curriculum, dependency or licence changes.
- Any existing content item in the student's pinned course release can have one private note. Ownership comes from the live session and its enrollment; submitted owner/release/enrollment fields are rejected. Foreign or missing items return 404 without exposing another note. Existing pinned release behavior is retained.
- PUT requires `{ mutationId, itemId, expectedRevision, expectedStudentId, body }`. The URL and submitted item must match. The student ID is a mandatory stale-form check, never ownership authority. Strict Zod validation limits plain text to 20,000 UTF-16 code units, consistent with JavaScript string length and a future native textarea counter/limit. Text, whitespace, newlines, Serbian scripts, emoji and HTML-like text are preserved without evaluation.
- Notes have their own revisions, independent of enrollment progress and other notes. An absent note returns an empty body, revision 0 and null timestamps without inserting records. The first acknowledged save is revision 1. Empty text clears the body while retaining its record, original creation time and revision; each new accepted request advances the revision, including unchanged text.
- Shared enrollment-scoped receipts use a note-domain request hash. Note writes and receipts commit together in an IMMEDIATE SQLite transaction. Exact retries return the original acknowledged body/revision/timestamps, including after later edits and process restart; GET returns the latest confirmed note. The same key with different content, or a note/progress key collision, returns 409 rather than replaying another operation.
- A stale note revision returns 409 with this account's latest `currentState` and revision. Account changes return 403; expired/revoked/absent sessions return 401, including on receipt retries. Storage failures return a safe 503 with no private text or database details.
- Responses use the existing `{ data, revision }` / structured error envelope and `Cache-Control: no-store`. Local Host/Origin checks apply to reads and writes; writes require signed session-bound CSRF. Only this endpoint permits a bounded 128 KiB JSON request, enough for a fully escaped 20,000-unit note. Existing endpoints retain their 32 KiB default.
- Notes do not write learning credit, activity, preparation, task decisions, enrollment revision, Last opened or active resume state. Normal authentication session renewal can still occur.

These settle minor unspecified details: mandatory form-account guard, absent-note representation, retaining cleared records, unchanged-text request revisions and the shared receipt namespace. No source curriculum interpretation changed.
