Verified 2026-10-05. This focused step is complete. The final MVP and full A01–A26 acceptance remain open.

## Behavior and decisions

One pure required-unit calculation now supplies course, module, week and day fractions, floor percentages, completed days, remaining lessons/exercises and completion times. Descendant membership follows the published hierarchy; denominators are derived, not hardcoded. Started work and Needs review award no completion credit. Empty scopes are Not applicable. Complete means every required descendant is complete; its time is the latest required-unit completion time. Reopening removes completion from the unit and every containing scope immediately.

The dashboard now places Continue first, followed by four compact counts and the current module/week/day. The same resolver drives the GET Continue redirect and the presentation, honoring preparation, incomplete active cursors, same-day fallback, earlier gaps and all-complete. A later chosen unit is explicitly out of sequence, with a separate link to the earliest incomplete work. Active study and Last opened reference are shown separately. Saved/completion/reference times use the student's stored timezone. Preparation is reminded only while advisory checks remain or acknowledgment is missing. The latest attempted incomplete checkpoint repeats its exact source criterion and existing review links.

Enrolled course overview and Progress show all six module rollups. Module pages list weeks, week pages list days and day pages show independent study/exercise state. Progress filters All, Incomplete, Completed and Needs review without writing records. Completed course state offers the final retrospective and Appendix G. Dedicated lesson/exercise views also show confirmed completion times. No prerequisite locks or extra completion units were introduced.

Canonical progress remains in existing owned SQLite records. Snapshot adds derived unit state and existing cursor/reference timestamps; no migration or stored aggregate. Successful enrollment/progress/cursor mutations revalidate dashboard and course pages. Read-only overview state is keyed by account/revision so refreshed props cannot retain an earlier user's overview. Source archive, published curriculum, dependencies and licences are unchanged. Recent activity and section-anchor tracking remain subsequent steps; no empty activity placeholder was added.
